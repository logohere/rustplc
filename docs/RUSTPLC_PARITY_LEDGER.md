## Direct Runtime v3/v4 parity

The pinned macOS desktop does not use Orchestrators: its upstream Orchestrator adapter is intentionally a no-op and the Orchestrators UI is gated off. The Rust port therefore implements the actual macOS direct-runtime path rather than adding a dead Orchestrators screen.

Implemented direct Runtime behavior:

- HTTPS target connection on port 8443 with certificate/hostname verification enabled by default; self-signed/unverified Runtime TLS requires an explicit per-project opt-in and visible MITM warning;
- unauthenticated `/api/get-users-info` probe, first-user bootstrap, login, in-memory bearer-token session, and logout; reusable passwords are not retained after login, and an expired token is cleared so the user must explicitly authenticate again;
- `/api/status`, `/api/start-plc`, `/api/stop-plc`, and `/api/compilation-status` flows;
- one shared Rust generator now feeds local Simulator, Runtime v3, and Runtime v4 targets so there is no second transpile/codegen path;
- Runtime v4 bundle generation matches the pinned root ZIP contract: `program.st`, split generated C++, `generated.hpp`, `defines.h`, `debug-map.json`, `c_blocks.h`, empty EtherCAT config, and owned runtime headers under `strucpp_runtime/include`;
- Runtime v3 uploads the generated `program.st` multipart payload; Runtime v4 uploads the generated ZIP;
- compilation polling streams only new log lines, classifies pinned `[INFO]/[WARN]/[ERROR]/[DEBUG]` prefixes, tolerates transient polling errors with the pinned bounded retry count, and stops on SUCCESS/FAILED/timeout;
- post-build start retries pinned BUSY responses until START:OK/ALREADY_RUNNING or timeout;
- Runtime v4 probes `/api/version` and enforces the upstream STruC++ minimum `>= 4.1.0`, including accepting `4.1.0-rc.*` and rejecting unknown/legacy `v4` responses before upload;
- successful v4 deploy automatically attempts MD5-verified remote debugger attach; manual Attach Debugger is also available after login;
- unsaved editor tabs block remote deployment/debug attach so stale on-disk project state is never silently compiled;
- direct-runtime status polling and Start/Stop/Refresh/Build & Deploy controls are exposed inside Device Configuration for Runtime targets.

Runtime bundle, multipart upload, login/session-expiry, TLS-policy, version-gate, compilation-poll, start-after-build, and remote debug transport regressions pass locally.

## Rule for claiming parity

A feature is not “ported” because Rust source exists.

A parity claim requires the highest applicable evidence level:

```text
unit/source parity
    -> upstream regression/differential evidence
    -> native/protocol integration
    -> user workflow
    -> packaged release artifact
```

For RustPLC 1.0, this ledger contains no known release-blocking unapproved divergence against the documented macOS pins. Future OpenPLC baseline updates require a new differential cycle and RustPLC release; they do not retroactively redefine the 1.0 claim.
